Cheat sheet

EnzymeX BLAST + HMMER  ·  4 August 2026
The yearbook — a book of 273,000 people. A photo = a protein sequence. A job title = an EC number. A stranger's photo comes in; you find who they look like, and their job titles are your evidence. | warehouse = enzymesdata (MySQL) | filing cabinet = BLAST db | family portrait = profile HMM | name cards = metadata.sqlite3 | edition no. = build ID
Print the book once offline. Every search reads only that book, three ways, and never touches the database.

The demo — 4 beats

1. /health tab. Point at the build ID, then at reachable: false sitting next to three oks.
“MySQL is down on this machine. I left it off. All three searches still work, because they read files, not the database.”
2. Paste SOD2. Tick all three methods. ~2 s. Read the grey box at the top out loud. Top hit is SOD2 itself, right EC, both coverage columns near 1.00.
“Whole photo matched to whole photo. That's a real match.”
3. Paste GFP. Set it up first: “jellyfish protein, does no chemistry, has no EC number.” 25 hits come back at up to 97.5%, 15 carrying EC numbers. Pause — let it look like a failure. Then point at Source (all pdb), then query 1.00 / subject 0.55.
“It's a group photo. PDB is full of enzymes with GFP glued on so people can see them. I matched the GFP half. The EC belongs to the half I didn't match. BLAST has no field for that number — I compute it.”
4. ls var/jobs/<id>/ — query, raw output from all three tools, stderr, parsed result. Skip if short on time.

Commands

— start the server on 127.0.0.1:8000. Run first, leave the terminal open.
make health
— the health JSON in the terminal. Same as the /health tab.
make status
— what is currently built: build ID, sequence count, profile count.
make versions
— every tool version, if anyone asks.
make refbuild
— reprint the whole yearbook. The 4-minute one.
ls var/jobs/<id>/
— one search's folder.
head var/jobs/<id>/blastp_hits.tsv
— BLAST's raw output, untouched. Show this if asked about output format.
make clean
— do not run this. It deletes the built yearbook.

Say these

Positioning
— “Evidence, not a prediction. It sits next to ECPICK, HIT-EC and CLEAN, not instead of them.”
Models vs mine
— they always answer, even with no known relative. Mine only answers if something resembles you, can say nothing, and always shows its work. Do not say “more accurate”.
Three tables
— never merged. Each tool scores on its own scale; one ranking would fake a comparison.
Volunteer it
— profiles are not built on the 272k set yet. Say it before they find it.
DIAMOND — ask, don't claim
— BLAST has no subject-coverage field, but DIAMOND can emit it. “Does your DIAMOND output already have subject coverage? I'd rather use your column.”

The two asks — don't leave without

1. Repo access
— datax-lab/enzymex 404s for me. I used the public HIT-EC Swiss-Prot/PDB file and built 272k to prove it scales, but the real local DB has proper source tags.
2. Placement
— where should BLAST/HMMER appear on the result page next to the existing DIAMOND workflow.

If asked what something means

Source
— how much the job title is worth. swissprot: a human curator read the paper. pdb: someone solved the structure, but the entry is whatever was in the crystal — that is where the group photos come from. TrEMBL and KEGG dropped: machine-guessed labels.
E-value
— how many matches this good you'd expect by pure luck. Smaller is stronger. Not comparable between the three methods.
Coverage
— how much of the query, and how much of the hit, the match spans. The gap between the two is the group-photo alarm.
Families
— I build them, nothing upstream provides them. MMseqs2 groups lookalikes, MAFFT lines them up, hmmbuild blends them into one portrait. Only hmmscan uses them; phmmer builds a throwaway one from the query instead.
Filters
— under 30 letters out, over 10,000 out, >10% unreadable letters out, duplicates merged, non-Swiss-Prot/PDB out. Every rejection logged with a reason in skipped.tsv.
Build ID
— fingerprint of the sequences plus the rules. Same data and rules → same ID. Change either → new ID automatically.
Quarterly cron
— theirs, already running. It restocks enzymesdata. My build just hangs off it.

Defending the stack

Python
— same as EnzymeX. Nothing new for them to maintain.
FastAPI
— only my test server's web layer. The search code imports no web framework, so their Pyramid app calls it as a plain function. No rewrite.
MySQL / SQLite
— MySQL read-only for the build. SQLite is one file, no server, which is why search has no DB connection.
micromamba
— only because BLAST+, HMMER, MAFFT and MMseqs2 are standalone programs, not pip packages.
The one line
— “Same language, same database engine, and the search code has no web framework in it, so it drops into your existing scheduler.”
