Biology

Protein sequence
— a string of letters, one per amino acid. All these tools ever look at.
Enzyme
— a protein that speeds up a chemical reaction.
EC number
— four-part code naming that reaction, e.g. 1.15.1.1. Names a reaction, not a family.
Fusion construct
— two proteins deliberately joined into one. Common in PDB. The GFP problem.
GFP
— jellyfish protein that glows green. Not an enzyme. Used as my negative control.
SOD
— superoxide dismutase. My positive control. Has Cu/Zn and Mn/Fe versions that share one EC and look nothing alike.

Data and formats

FASTA
— plain text sequence format: a > header line, then the sequence letters. Every tool reads it.
Swiss-Prot
— manually reviewed protein database. High quality. One of my two sources.
PDB
— Protein Data Bank. Proteins with an experimentally solved 3D structure. My other source.
TrEMBL / KEGG
— the other two sources EnzymeX pulls. Excluded, per Dr. Kang.
enzymesdata
— the EnzymeX MySQL table with all those sequences plus EC, source and description. I read a copy.
Accession / UniProt ID
— the public ID for an entry, e.g. P04179.
Build ID
— a stamp on every file produced by one export, so a hit and its EC always come from the same snapshot.

Tools

BLAST / blastp
— the standard sequence search tool since 1990. Aligns your sequence against every known one and ranks matches. blastp = protein vs protein.
HMMER
— a different search toolkit using probability models instead of direct alignment. Better at distant relatives.
phmmer
— HMMER, one sequence against every reference. Same coverage as BLAST, different maths.
hmmscan
— HMMER, one sequence against family models. Returns a family, not an individual protein.
Profile HMM
— a statistical portrait of a protein family, built from an alignment of its members. What hmmscan searches.
MMseqs2
— very fast clustering. I use it to group references into families by sequence similarity.
MAFFT
— multiple sequence aligner. Lines up a cluster so a profile can be built from it.
makeblastdb, hmmbuild, hmmpress
— index builders. Turn a FASTA or alignment into something searchable in milliseconds.
DIAMOND
— a faster, less sensitive BLAST alternative. EnzymeX already runs it to pick proteins for the interpretation images.

What the scores mean

E-value
— how many matches this good you would expect by pure luck. Smaller is stronger. 1e-100 is essentially impossible by chance.
Bit score
— raw strength of a match. Unlike E-value it does not change with database size.
Percent identity
— what fraction of aligned letters are literally the same. BLAST reports it; HMMER does not.
Query / subject
— query is what the user submitted, subject is the known protein it matched.
Coverage
— how much of the query, and how much of the subject, the alignment spans.
HSP
— one matching stretch inside an alignment. A hit can have several; I merge them to get subject coverage.
EC purity
— how consistent the EC labels are inside one of my clusters. Measured, not assumed.

450 / 452
— same for the whole top-25 list, not just the winner. The two that differ are tie-ordering between BLAST versions.
272,112
— how many known proteins a search compares against.
-evalue 1e-3
— my cutoff. Anything weaker than 1-in-1,000-by-chance is not shown.
-max_target_seqs 500
— how many hits BLAST keeps internally. It is a search cutoff, not a top-N filter, so I rank to 25 afterwards in code.
35% identity / 80% coverage
— the clustering rule. Two sequences join a family if 35% of letters match across 80% of both.
13 / 4 / 5
— how many separate sequence families one single EC number split into. This is why profiles are not built per EC.

— GFP's top hit. Nearly the same protein, zero chance of coincidence — and still the wrong answer, because it is a fusion.

— the match covers all of my sequence but only 55% of theirs. That gap is the fusion signature.

Stack words — what each one is

Python
— the language everything is written in, mine and EnzymeX's.
FastAPI
— a Python web framework. The web layer of my test server. Modern, lightweight.
Pyramid
— an older Python web framework. What the EnzymeX site runs on. Same job as FastAPI.
Jinja2
— a template engine. Takes an HTML file with blanks and fills them with your data. Both sides use it.
uvicorn / uWSGI
— the programs that keep a Python web app running and hand it incoming requests. Mine uses uvicorn, EnzymeX uses uWSGI.
nginx
— the web server sitting in front of all that, taking traffic off the internet.
Pydantic
— a Python library that checks incoming data is the right shape before you use it. Catches bad input early.
MySQL
— the database EnzymeX stores everything in. A server you connect to.
SQLite
— a database that is just one file, no server. My search reads one of these instead of connecting to MySQL.
PyMySQL
— the Python library that talks to MySQL. Pure Python, so nothing needs compiling on the server.
pytest
— the Python testing framework. "183 tests pass" means pytest ran them.
micromamba
— an environment manager. Needed because BLAST+, HMMER, MAFFT and MMseqs2 are standalone programs, not pip packages.
Docker Compose / systemd
— two ways to keep the server running and restart it if it dies.
cron
— the Linux scheduler that runs a command on a timetable. EnzymeX pulls new data quarterly with it.
Scheduler / runner
— EnzymeX's background job system. It runs ECPICK, HIT-EC and CLEAN. My searches would become another step in it.

Slide notes — the point of each

1 Title
— evidence beside the three predictions, not a fourth predictor. Say it once, up front.
2 Workflow
— five steps, and which two run offline. Step 1 is the only database connection in the whole flow.
3 Tech stack
— same language, same database engine as EnzymeX. The search code imports no web framework, so it drops in.
4 Build once
— the build is the only thing that touches the database. A search reads files, so it cannot slow or leak it.
5 Three searches
— separate tables because the three scores are different quantities. Merging them would invite a false comparison.
6 Profiles
— the judgement call. Clustered by sequence because one EC can hold unrelated proteins. Mn-SOD test proves it works.
7 Validation
— two BLAST versions, his parameters, same top hit every time. Correctness, not accuracy. Do not let it get quoted as accuracy.
8 Real data
— tell it as a story: a clean test set could not have produced the GFP failure, real data did, and the coverage column caught it.
9 Next
— access is the only blocker. Everything after it is about a day each. Ask early, not at the end.
