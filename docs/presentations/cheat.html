Biology

Protein sequence
— a string of letters, one per amino acid. All these tools ever look at.
Enzyme
— a protein that speeds up a chemical reaction.
EC number
— four-part code naming that reaction, e.g. 1.15.1.1. Names a reaction, not a family.
Fusion construct
— two proteins deliberately joined into one. Common in PDB. The GFP problem.
GFP
— jellyfish protein that glows green. Not an enzyme. Used as my negative control.
SOD
— superoxide dismutase. My positive control. Has Cu/Zn and Mn/Fe versions that share one EC and look nothing alike.

Data and formats

FASTA
— plain text sequence format: a > header line, then the sequence letters. Every tool reads it.
Swiss-Prot
— manually reviewed protein database. High quality. One of my two sources.
PDB
— Protein Data Bank. Proteins with an experimentally solved 3D structure. My other source.
TrEMBL / KEGG
— the other two sources EnzymeX pulls. Excluded, per Dr. Kang.
enzymesdata
— the EnzymeX MySQL table with all those sequences plus EC, source and description. I read a copy.
Accession / UniProt ID
— the public ID for an entry, e.g. P04179.
Build ID
— a stamp on every file produced by one export, so a hit and its EC always come from the same snapshot.

Tools

BLAST / blastp
— the standard sequence search tool since 1990. Aligns your sequence against every known one and ranks matches. blastp = protein vs protein.
HMMER
— a different search toolkit using probability models instead of direct alignment. Better at distant relatives.
phmmer
— HMMER, one sequence against every reference. Same coverage as BLAST, different maths.
hmmscan
— HMMER, one sequence against family models. Returns a family, not an individual protein.
Profile HMM
— a statistical portrait of a protein family, built from an alignment of its members. What hmmscan searches.
MMseqs2
— very fast clustering. I use it to group references into families by sequence similarity.
MAFFT
— multiple sequence aligner. Lines up a cluster so a profile can be built from it.
makeblastdb, hmmbuild, hmmpress
— index builders. Turn a FASTA or alignment into something searchable in milliseconds.
DIAMOND
— a faster, less sensitive BLAST alternative. EnzymeX already runs it to pick proteins for the interpretation images.

What the scores mean

E-value
— how many matches this good you would expect by pure luck. Smaller is stronger. 1e-100 is essentially impossible by chance.
Bit score
— raw strength of a match. Unlike E-value it does not change with database size.
Percent identity
— what fraction of aligned letters are literally the same. BLAST reports it; HMMER does not.
Query / subject
— query is what the user submitted, subject is the known protein it matched.
Coverage
— how much of the query, and how much of the subject, the alignment spans.
HSP
— one matching stretch inside an alignment. A hit can have several; I merge them to get subject coverage.
EC purity
— how consistent the EC labels are inside one of my clusters. Measured, not assumed.

— how many known proteins a search compares against.
-evalue 1e-3
— my cutoff. Anything weaker than 1-in-1,000-by-chance is not shown.
-max_target_seqs 500
— how many hits BLAST keeps internally. It is a search cutoff, not a top-N filter, so I rank to 25 afterwards in code.
35% identity / 80% coverage
— the clustering rule. Two sequences join a family if 35% of letters match across 80% of both.
13 / 4 / 5
— how many separate sequence families one single EC number split into. This is why profiles are not built per EC.

Where the output lives

/jobs/<id>
— the results page. Submitting redirects here automatically.
/jobs/<id>/results.csv · .json
— links in the grey strip at the top of that page.
var/jobs/<id>/
— on disk: query.fasta, blastp_hits.tsv, phmmer_tblout.txt, phmmer_domtblout.txt, hmmscan_tblout.txt, hmmscan_domtblout.txt, *_full.txt, *.stderr.txt, results.json.
outfmt 6
— BLAST's raw output: a tab-separated table, no headers. 13 columns, my choice.
--tblout / --domtblout
— HMMER's equivalents. tblout = one row per sequence matched, domtblout = one row per region.
qlen slen sstart send
— the four columns I asked for on purpose. Subject coverage is computed from these. BLAST has no field for it.
Normalized
— three formats retyped onto one shape (hit id, EC, identity, E-value, bits, coverage), kept in three tables because the scores are not comparable.
Show it as
— raw blastp_hits.tsv → results.json → the page. Answers Kang's output-format question in 40 seconds.

Positioning, and the two asks

Models vs mine
— ECPICK / HIT-EC / CLEAN always answer, even with no known relative. Mine only answers if something resembles you, can say nothing, and always shows who and how similar.
Do not say
— “more accurate”. Say: they can predict where I cannot; when I answer, the answer is checkable.
DIAMOND — careful
— BLAST+ has no subject-coverage field, but DIAMOND can emit scovhsp. Do not claim they lack it. Ask: “does your DIAMOND output already have it? I'd rather use your column.”
Ask 1 — access
— datax-lab/enzymex 404s. Used the public HIT-EC Swiss-Prot/PDB file and built 272k to prove scale; need the real local DB with proper source tags.
Ask 2 — placement
— how should BLAST/HMMER appear on the result page next to the existing DIAMOND workflow.
Say first
— profiles are not built on the 272k set yet. Volunteer it before they find it.
Families
— I build them, nothing upstream provides them. Used by hmmscan only; phmmer builds a throwaway profile from the query instead.
Quarterly cron
— theirs, already running. It restocks enzymesdata. My build just hangs off it: restock → rebuild → new build ID.

Stack words — what each one is

FastAPI
— Python web framework. The web layer of my test server.
Pyramid
— older Python web framework. What EnzymeX runs on. Same job as FastAPI.
uvicorn / uWSGI
— keep a Python web app running and hand it requests. Mine uses uvicorn, EnzymeX uses uWSGI.
Pydantic
— checks incoming data is the right shape before you use it.
MySQL
— the database EnzymeX stores everything in. A server you connect to.
SQLite
— a database that is just one file, no server. My search reads one instead of connecting to MySQL.
PyMySQL
— the library that talks to MySQL. Pure Python, so nothing needs compiling on the server.
micromamba
— environment manager. Needed because BLAST+, HMMER, MAFFT and MMseqs2 are programs, not pip packages.
Scheduler / runner
— EnzymeX's background job system. Runs ECPICK, HIT-EC and CLEAN. My searches become another step in it.
